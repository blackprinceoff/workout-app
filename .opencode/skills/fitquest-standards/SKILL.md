# FitQuest — стандарти коду

Мета: кожна зміна має бути маленькою, безпечною для збережень і впізнаваною в коді.
Правила нижче — не загальні поради, а факти цього репозиторію. Якщо вони суперечать
твоєму інстинкту, правила мають рацію.

## 0. Зелений гейт (обов'язково, у такому порядку)

```bash
npm run test && npm run lint && npm run build
```

- `test` = `vitest run`; `lint` = `oxlint`; `build` = `tsc -b && vite build`.
- Усі три мають бути зеленими до коміту. Якщо ні — відкоти або виправ, не коміть.
- `tsconfig.app.json` містить лише `src`, тому `tests/` **не типізуються** `tsc -b`.
  Тип-помилка в тесті не зупинить збірку — перечитуй свій тест очима.
- Форматера в проєкті немає (ні Prettier, ні Biome) — тримайся навколишнього коду руками.
- `oxlint` увімкнено з мінімальним набором правил (`react/rules-of-hooks`,
  `react/only-export-components`), без type-aware правил. Він не ловить `any`,
  небезпечні `React Hook` і мертвий код — це твоя відповідальність.

## 1. Стиль коду

- Без `;` у кінцях рядків, одинарні лапки, 2 пробіли, trailing comma у мультирядкових
  списках/об'єктах (як у сусідньому коді).
- `import type { X } from ...` для типів — увімкнено `verbatimModuleSyntax`.
- Імпорти локальних модулів **з розширенням**: `from './storage.ts'`, `from '../App.tsx'`
  (`allowImportingTsExtensions`), порядок: react → сторонні → локальні.
- Без коментарів у коді, без TODO, без емодзі. Пояснення намагайся перенести в
  ім'я змінної або в структуру.
- UI-тексти, підписи `aria-label`, назви тестів — **українською**.
- Імена — англійською, зрозумілі; експортові функції без префікса під модуль.

## 2. Стан, localStorage, збереження (найризикованіше місце)

Усе мутабельне живе в одному місці: `src/state/GameContext.tsx` (`Action` → `reducer` →
`GameProvider`). UI не змінює стан напряму, тільки через дії з `useGame()`.

Якщо додаєш **поле стану**, обязково пройди всі 5 кроків — інакше старі сейви зламаються:

1. Тип у `src/game/types.ts` + дефолт у `initialProfile`/`initialSettings`/`createInitialState`.
2. `normalizeState()` у `storage.ts` — валідація/дефолт при завантаженні.
3. Новий блок міграції в `migrateRaw()`: `if (version < N) { ... }`.
4. **Бump `STATE_VERSION`** у `src/game/constants.ts` (зараз 16) — інакше міграція не запуститься.
5. Тест на міграцію: старий сейв → нова версія → поле має коректне значення.

Правила сумісності:

- Не змінюй `STORAGE_KEY` і не переписуй `exportState`/`importState` — це формат користувацького
  файлу. Старі імпорти мають лишатися валідними.
- `rollover()` викликається з інтервалу 30 с — не робіть його важким; він має бути
  ідемпотентним (перевір `tests/storage.test.ts`).
- Мутабельні об'єкти в стані не копіюй на місці:Spread-іть (`{ ...state, x: 1 }`),
  бо тести порівнюють посилання.

## 3. Баланс і XP

Будь-яка зміна XP, кривої рівнів, коефіцієнтів інтенсивності/навантаження — це
результат `tests/economy.test.ts`:

- «нормальний» профіль → рівень 100 за **660–800 днів**;
- «дисципліна» → **320–460 днів**;
- легкий старт: низькі рівні — вправи від колін/з опорою, 1 підхід, warm-up 0.75–0.9.

Не «покращуй» баланс, навіть якщо нікому не подобається: довгий прогрес — дизайн-вимога.
Змінив формулу — переконайся, що тест зелений, і напиши в `AUTO_IMPROVE.md`, що
перевіряв межі.

## 4. React: сторінки й компоненти

- Сторінки — `src/pages/*`, спільні шматки — `src/components/*`.
  **Сторінка не повинна переростати ~400 рядків.** Зараз `Progress.tsx` ≈ 1490,
  `Quests.tsx` ≈ 1390 — не додавай туди ще блоків, а винось у компонент/хелпер.
- Іконки — тільки через `src/components/Glyphs.tsx` та `iconMaps.ts` (lucide). Ніколи емодзі.
- `type="button"` на кожній кнопці, бо є форми й кліки по вкладках.
- Не дублюй логіку: `dateKey`, `shiftDateKey`, `lastNDays`, `formatUa` (game/dates),
  `clamp` (state/storage), `sound.ts` (звук), `EventLayer` (модалки/тости).
- `as any` заборонено (є 5 залишків). Для `<select>` з union-типом роби тимізований cast:
  `onChange={(e) => setSort(e.target.value as SortKey)}`.
- Хуки — тільки на верхньому рівні компонента; без власного стану там, де його дає контекст.
- Не залишай мертвий код: сторінка, яку ніхто не імпортує, не «полює» фічями.
  Перевіряй досяжність (`grep` по імені файлу) перед роботою над сторінкою.

## 5. Стилі та теми

- Пріоритет: клас із `src/index.css` → `style={{}}` лише для динамічних значень
  (width у %, колір із налаштувань).
- Тільки токени `var(--…)`, ніколи «сирий» колір у стилі. Так працюють і світла тема
  (`:root[data-theme="light"]`), і стабільні розміри.
- Типовий інлайн-стиль (`padding: 6px 12px`, `borderRadius: 6`, `minWidth: 140`) —
  це class. Зараз їх 640; кожен новий такий — борг, не копіяй їх у новий код.
- Семантичні класи з наявньої шкали (`panel`, `btn btn-sm btn-gold`, `bar bar-fill`,
  `section-mb`, `page-title`, `page-sub`), не нові випадкові імена.

## 6. Доступність (дрібне, але дешеве)

- Кожен контрол має доступне ім'я: `aria-label` або видимий `<label>`.
- Фільтри/сортування — семантика відповідає дії: група кнопок-фільтрів не потребує
  `role="tablist"`/`aria-selected`; табки — тільки якщо реально табки з клавіатурною навігацією.
- Іконка-кнопка — `aria-label`; декоративна іконка — `aria-hidden`.
- Не лови мишу/клавіатуру двічі: один обробник на елемент, подія з конкретного елемента.

## 7. Тести

- `vitest`, середовище **node, jsdom у проєкті немає**. Не пиши тестів на рендер
  компонентів і не імпортуй testing-library — їх немає в залежностях.
- Тестуй чисте: `reducer`, `src/game/*` (генерація квестів, XP, досягнення, дати),
  `storage` (міграції, нормалізація, rollover).
- Імена `it()` — українською, описують **поведінку**, а не реалізацію:
  «Зберігає позначені "болячі" групи при зміні інтенсивності».
- Одна поведінка — один `it()`. Для сусідніх кейсів є готовий хелпер `stateFor()`
  у `tests/state.test.ts` — перевикористовуй замість копіювання стану.
- Змінив поведінку — додав/оновив тест у тій же ітерації, не «потім».
- Детермінованість: не використовуй `Math.random()`/`Date.now()` без фіксації
  (є `hashSeed`/`mulberry32` і `dateKey()` для стабільних тестів).

## 8. Чекліст перед комітом

- [ ] `npm run test && npm run lint && npm run build` — усі зелені.
- [ ] Немає `any`, `console.log`, коментарів, емодзі, TODO у новому коді.
- [ ] Новий стан пройшов усі 5 кроків розділу 2 (якщо додавав поле).
- [ ] Зміни балансу — `tests/economy.test.ts` у межах.
- [ ] Нова фіча має тест або зрозумілу причину, чому ні.
- [ ] Фіча реально досяжна: її видно в навігації/розкритті з `App.tsx`.
- [ ] Один малий атомарний коміт, опис **англійським одним рядком** (`feat:` / `fix:`).
- [ ] `git push origin main`, remote не змінювався, у коміті немає секретів.
- [ ] Один рядок підсумку в `AUTO_IMPROVE.md` (✔ + що зроблено), черга оновлена.

## Швидка самоперевірка

```bash
grep -rn "as any\|: any" src/                    # має бути порожньо
grep -rn "console\.log" src/                     # має бути порожньо
grep -rn "style={{" src/ | wc -l                 # не має зростати
grep -rn "STATE_VERSION = " src/game/constants.ts
```
